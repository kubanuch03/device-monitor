# Развитие Device Monitor: исследование и план

Исследование и план — 09.11.2026, статус — на 10.11.2026.

## Что взяли у похожих систем

| Система | Что взяли | Где у нас |
|---|---|---|
| Uptime Kuma | подтверждение падения N проверками, окна обслуживания, «не тревожить» | `device_monitor/alerts/rules.py` |
| Prometheus Alertmanager | подавление: упал объект целиком → одно сообщение, а не двадцать | `alerts/rules.py` (site outage) |
| Gatus / Healthchecks.io | сторож самого монитора (heartbeat-URL) | «Оповещения» → сторож |
| Dahua DSS / HertzBeat | здоровье камер сверх «порт открыт»: часы, NTP | `vendors/dahua.py` (`clock_health`) |
| NetBox | инвентарь: модель, серийник, прошивка, MAC | сбор сведений (`vendors/`) |
| Frigate / go2rtc | просмотр RTSP в браузере через go2rtc | страница видео |
| Teleport / Tailscale app access | доступ к веб-интерфейсу устройства за NAT без настройки браузера | встроенный TCP-релей (`access/relay.py`) |

## Чего не делаем и почему

- **Zabbix, LibreNMS, Checkmk** — тяжело для ~100 устройств, и они не умеют наше
  главное: объекты за SOCKS/SSH и одинаковые подсети на разных объектах.
- **Замена VPN на Tailscale/NetBird** ради пересечения подсетей — NetBird его не
  решает, Tailscale 4via6 требует узел на каждом объекте и замены всех WireGuard.
- **Микросервисы** — один процесс + SQLite для этого масштаба надёжнее; отдельно
  живут только go2rtc (видео) и, при необходимости, агенты на объектах.
- **Переписывать сервис на Rust** — он 99% времени ждёт сеть, выигрыша нет;
  на Rust — только программа для Linux (окно, трей).
- **Автодобавление найденного без подтверждения** — в сети объекта бывают чужие
  устройства; одинаковая модель на новом адресе не доказывает «переезд».

## Как работаем над кодом

- Каждое изменение — тесты (`.venv/bin/python -m pytest`) и независимое ревью
  перед коммитом. Ревью регулярно находило блокеры, которые тесты пропускали.
- Регрессионный тест сначала прогоняется на заведомо сломанном коде — он обязан
  упасть (урок: проверочный скрипт однажды выдал ложное «0 из 40»).
- CI на GitHub гоняет тесты на каждый push (`.github/workflows/tests.yml`).
- Агенты проекта для Claude Code: `.claude/agents/tester.md`, `.claude/agents/reviewer.md`.
